# External plugin repository findings

## FiorenMas/mihon-extensions

GitHub repository: https://github.com/FiorenMas/mihon-extensions

The repository has no published releases. Its root contains `index.json`, `index.min.json`, `index.pb`, `repo.json`, and separate `apk/`, `jar/`, and `icon/` directories. The latest commit is generated by GitHub Actions and updates the repository. This means an importer must not rely on GitHub Releases or `.jar` release assets for this repository; it should discover and import the root JSON catalog, preferably `index.min.json` or `index.json`, and accept repository-root JSON files exposed through the Git tree API.

## beer-psi/tachiyomi-unofficial-extensions

GitHub repository: https://github.com/beer-psi/tachiyomi-unofficial-extensions

The repository is primarily an extension source-code/build repository (`src/`, `core/`, `lib/`, Gradle build files), not a simple published catalog repository. It has GitHub releases/tags, but the catalog JSON may be generated or published through the project's build/release workflow rather than being present as a root index file. An importer should inspect release assets and known generated repository paths in addition to root-tree JSON, and must fail gracefully with a detailed error when no compatible catalog JSON is available.

## Scope clarification

The GitHub-avatar metadata icon (`https://github.com/<owner>.png`) is intended for online-imported plugin/repository metadata. It must not be assigned to plugins imported from local storage. Tachiyomi/Mihon external repositories imported online can use online repository metadata where a GitHub owner is available, while local JAR imports retain the existing generic/local icon behavior.

## Verified catalog endpoints (2026-08-27)

- `FiorenMas/mihon-extensions`: the working catalog endpoint is `https://raw.githubusercontent.com/FiorenMas/mihon-extensions/repo/index.min.json` (also expected at `repo/index.json`). It returns a JSON array of extension objects with `name`, `pkg`, `apk`, `lang`, `code`, `version`, `nsfw`, and `sources[]`; the verified current data contains two compatible entries. The repository root branch is not the catalog branch, so discovery must inspect GitHub tree/branches or accept the explicit raw URL.
- `beer-psi/tachiyomi-unofficial-extensions`: the README explicitly advertises `https://beer-psi.github.io/tachiyomi-unofficial-extensions/index.min.json`; the same JSON is available at `https://raw.githubusercontent.com/beer-psi/tachiyomi-unofficial-extensions/repo/index.min.json`. It returns the same standard array shape, including `apk` names such as `tachiyomi-en.fakku-v1.4.3.apk` and `tachiyomi-vi.cuutruyen-v1.4.15.apk`. The source repository itself is a Gradle project, but its `repo` branch and GitHub Pages output are valid catalog sources.
- `https://raw.githubusercontent.com/FiorenMas/mihon-extensions/repo.json` was not a valid content endpoint in the check; do not claim root `repo.json` support without another verified source.

Implementation implication: repository discovery should include GitHub `repo` branch candidate paths (`repo/index.json`, `repo/index.min.json`, `index.json`, `index.min.json`) in addition to default-branch JSON tree files, while parser compatibility remains limited to standard Tachiyomi array entries with downloadable APK names.
